# Machine Learning Practice

机器学习实验课「任务 4」的研究日志存档。14 天，从定协议到从头复现，每天一篇。

研究问题一句话：**不碰测试标签、不拿标签调参的前提下，近年的非深度异常检测方法能不能在结构化数据上赢过经典基线。**

简短回答：**没有赢。** 但这个否定的结论是有数据支撑的，而且比一个"前沿方法大获全胜"的故事更接近真实。

## 这是什么

不是教程，不是能直接 `pip install` 的库，是一份按天记录的研究过程档案。写下来是为了让每一步的判断都有出处：今天为什么换方向、哪个参数改过、哪次跑挂了、哪个数字后来被推翻。

日志里保留了失败。第一版参数顺序写错、seed 0 直接崩、堆栈留在文件里；ADERH 的 AP 输给 Isolation Forest，这个负结果原样留着，没有为了结论好看去挑最好的一次种子。

## 研究问题

无监督异常检测的麻烦在于：没有训练标签。这意味着模型的分数阈值、参数、甚至选哪个方法，都不能用测试集标签来定。一旦用标签挑模型，报出来的数字就是自欺欺人。

所以实验协议先冻结，再跑模型：

- 主指标 AP（对前列排序敏感，异常检测更看重这个），辅助指标 ROC-AUC
- 正式种子固定为 `[0,1,2,3,4]`，只报均值与标准差，不挑最好种子
- 测试标签只在最后评价时用一次
- 统一拆分、统一预处理，所有方法共用同一份数据

## 方法链路

| 环节 | 选择 |
|---|---|
| 数据 | UCI Shuttle（DOI `10.24432/C5WS31`，CC BY 4.0），29,402 / 12,345 拆分，测试集异常率 7.02% |
| 前沿候选 | ADERH（NeurIPS 2025，作者官方实现，MIT，PyPI 1.0.0） |
| 经典基线 | Isolation Forest、OCSVM、kNN、LOF |
| 线性与重构 | PCA(5) 重构误差 |
| 现代非深度基线 | ECOD |
| 结构诊断 | DBSCAN（只做密度结构诊断，不参与排名） |

方法取舍有记录：BRDAD 因为找不到可核验的官方实现被淘汰，RGLD 只在前沿讨论里出现，深度方法（DIF、Autoencoder、Deep SVDD）整体排除在正式比较之外。

## 主结果（按 AP 排序）

| 方法 | AP | 备注 |
|---|---|---|
| Isolation Forest | 0.9769 ± 0.0018 | 最稳 |
| ECOD | 0.9103 | 确定性运行 |
| ADERH | 0.8901 ± 0.0120 | 前沿候选，未超过前两者 |
| OCSVM | 0.3750 | |
| PCA(5) | 0.3560 | |
| kNN | 0.1928 | |
| LOF | 0.1344 | |

三条值得说的：

1. **ADERH 的 ROC-AUC 是 0.9935，看着很高，但 AP 只有 0.890。** 这个差距本身就说明问题：AUC 衡量整体排序，AP 更看重前 7% 那一段排得准不准。异常检测真正用在业务上时，看的正是前面那一小段。
2. **ADERH 五种子的 AP 标准差 0.0120，是 Isolation Forest 的 6.5 倍。** 效果没赢，稳定性也输了。
3. **负结果保留。** 如果只报 AUC，这个故事会变成"前沿方法表现优异"，但那是挑指标挑出来的结论。

## 目录

```
logs/
├── README.md                索引：14 天主线与阅读顺序
├── Day01 ~ Day14            每日日志，一天一篇
├── decision_log.md          只记会改变路线的决定，含放弃方案与代价
├── 日志到报告映射.md        每篇日志最后落到报告哪一节
└── 开源检查记录.md          隐私、路径、证据边界的检查结果
```

每篇日志都是同一个骨架：**研究目的 / 代码与数据 / 运行结果 / 结果含义** 四项摘要，加上当天的过程、卡点、证据路径和下一天要接什么。

`decision_log.md` 大概是这批文件里最值得看的一份。它不记录"我选了什么"，只记录"当时还有哪些选项、为什么放弃、放弃的代价是什么"。比如 D001 那条，把之前 DPC 项目砍掉转做异常检测，代价写得很清楚：旧代码和数字不能再用。

## 关于仓库边界

**本仓库只公开 `logs/`。** 日志里引用的 `results/`、`evidence/`、`src/`、`report/` 属于本地研究目录，没有随仓库发布。所以看到某篇写「证据：`results/aggregated/main_results_by_run.csv`」时，那个文件不在本仓库里。

这么做是有意的：完整项目目录里还留着带姓名、学号、本机路径的提交副本和报告生成脚本，不适合公开。日志本身已经过隐私检查，没有姓名、学号、绝对路径或本机用户名。

日志是素材账，不是报告正文。里面的数字要能回指本地结果文件才算数，这一点在 `日志到报告映射.md` 里也写明了。
